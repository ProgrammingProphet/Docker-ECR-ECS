## 1. What is Docker?
Docker is a platform for packaging an application with everything it needs (code, runtime, libraries, config) into a standardized unit called a **container**, so it runs the same on any machine. It's open source and written in Go. It builds on Linux kernel features: **namespaces** (isolation) and **cgroups** (resource limits).

**Analogy:** a shipping container. It doesn't matter what's inside or which ship, truck or port handles it, because the box is standardized.

## 2. Why Docker?
- **"Works on my machine" problem:** the same environment from dev to test to production
- **Fast:** containers start in seconds, not minutes
- **Lightweight:** they share the host kernel, so there is no full OS per app
- **Portable:** laptop, on-prem, AWS, Azure, anywhere Docker runs
- **Isolation:** apps with conflicting dependencies (Python 2 vs 3, Node 14 vs 20) coexist
- **Scalable and CI/CD friendly:** the foundation for microservices, Kubernetes, and pipelines

## 3. Virtual Machines vs Containers

| | Virtual Machine | Container |
|---|---|---|
| Virtualizes | Hardware | OS (process level) |
| Includes | Full guest OS + app | App + dependencies only |
| Size | GBs | MBs |
| Startup | Minutes | Seconds |
| Isolation | Strong (separate kernel) | Process-level (shared kernel) |
| Overhead | High | Low |
| Managed by | Hypervisor (VMware, Hyper-V, KVM) | Container runtime (Docker) |

**Key point for students:** VMs and containers aren't enemies. In the cloud, containers usually run *inside* VMs (for example Docker on an EC2 instance).

## 4. Docker Architecture
Docker uses a **client-server** model:
- **Docker Client (`docker` CLI):** what you type commands into
- **Docker Daemon (`dockerd`):** the background service that builds, runs and manages containers, images, networks and volumes
- **REST API:** how the client talks to the daemon (over a Unix socket or network)
- **Docker Registry:** stores images (Docker Hub, AWS ECR, Azure ACR)
- **Objects:** images, containers, networks, volumes

**Flow:** `docker run nginx` → client sends the request to the daemon → the daemon checks for the image locally → if missing, pulls it from the registry → creates and starts the container.

## 5. Docker Engine
The core runtime that does the actual work. It has three parts:
1. **dockerd** (the daemon)
2. **REST API**
3. **docker CLI**

Under the hood, dockerd delegates to **containerd**, which uses **runc** to create the container. Docker Engine is free and runs natively on Linux, which is what you'd install on a server or EC2 instance.

## 6. Docker Desktop
A GUI application for **Windows, macOS and Linux**, aimed at developers' machines. It bundles Docker Engine, the CLI, Docker Compose, a Kubernetes option, and a dashboard for containers, images and volumes. On Windows and Mac it runs a lightweight Linux VM (WSL2 or similar) behind the scenes, because containers need a Linux kernel.

**Note:** Docker Desktop has licensing terms for larger companies, while Docker Engine on Linux stays free. That's worth mentioning to students heading into jobs.

## 7. Images vs Containers
- **Image:** a read-only template containing the app and its dependencies, built in **layers**
- **Container:** a running instance of an image, with a thin writable layer on top

**Analogy:** image = class (or recipe), container = object (or the cooked dish). One image can spawn many containers.

```bash
docker pull nginx            # download the image
docker images                # list images
docker run -d -p 8080:80 nginx   # create + start a container
docker ps                    # list running containers
docker stop <id> && docker rm <id>
```

## Suggested live demo flow
1. Run `docker run hello-world` and walk through each step it prints, which shows the architecture
2. Run `docker run -d -p 8080:80 nginx` and open `localhost:8080`
3. Run the same image twice on different ports to show one image, many containers
4. Compare memory and startup time against launching a VM
