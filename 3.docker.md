# Stage 3: Dockerfile

## What is a Dockerfile?

A **Dockerfile** is a plain text file (named `Dockerfile`, no extension) containing step-by-step instructions to build a Docker image. Each instruction creates a **layer** in the image. Think of it as a recipe: Docker reads it top to bottom and produces a reusable, shareable image.

```
Dockerfile  --(docker build)-->  Image  --(docker run)-->  Container
```

## Core Instructions

### FROM
Sets the **base image**. Every Dockerfile starts with it.

```dockerfile
FROM node:20-alpine
FROM ubuntu:22.04
FROM python:3.12-slim
```
- Use a specific tag, not `latest`, for reproducible builds.
- `FROM scratch` starts with an empty image (used for static binaries).

### WORKDIR
Sets the **working directory** inside the container. Later `COPY`, `RUN`, and `CMD` run from here. It creates the directory if it doesn't exist.

```dockerfile
WORKDIR /app
```
Prefer this over `RUN cd /app`.

### COPY
Copies files from your **host (build context)** into the image.

```dockerfile
COPY package.json .          # single file to WORKDIR
COPY . .                     # everything in context to WORKDIR
COPY --chown=node:node . .   # set ownership
```
`ADD` also exists and can extract tar files and fetch URLs, but **use COPY** unless you specifically need those features.

### RUN
Executes a command **at build time** and saves the result as a new layer. Used to install packages, build code, etc.

```dockerfile
RUN apt-get update && apt-get install -y curl \
    && rm -rf /var/lib/apt/lists/*
RUN npm install
```
Chain commands with `&&` to keep the layer count down.

### EXPOSE
**Documents** which port the app listens on. It does **not** actually publish the port.

```dockerfile
EXPOSE 3000
```
To publish, you still need `docker run -p 8080:3000 myapp`.

### CMD vs ENTRYPOINT

Both define what runs **when the container starts**.

| | CMD | ENTRYPOINT |
|---|---|---|
| Purpose | Default command/arguments | The fixed executable |
| Override at `docker run` | Easily replaced by anything after the image name | Only with `--entrypoint` flag |
| Typical use | Default behavior | Making the container behave like a command |

```dockerfile
# CMD only
CMD ["node", "server.js"]
# docker run myapp           -> node server.js
# docker run myapp bash      -> bash (CMD replaced)

# ENTRYPOINT only
ENTRYPOINT ["ping"]
# docker run myapp google.com -> ping google.com

# Combined (common pattern)
ENTRYPOINT ["ping"]
CMD ["localhost"]
# docker run myapp            -> ping localhost
# docker run myapp google.com -> ping google.com
```

**Always use exec form** (`["cmd", "arg"]`) rather than shell form (`cmd arg`), so signals like SIGTERM reach your process and the container stops cleanly.

**Memory trick:** *RUN = build time. CMD/ENTRYPOINT = run time.*

## Build Custom Images

### Example: Node.js app

Project structure:
```
myapp/
├── Dockerfile
├── package.json
└── server.js
```

Dockerfile:
```dockerfile
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
EXPOSE 3000
CMD ["node", "server.js"]
```

### Build and run

```bash
docker build -t myapp:1.0 .          # build image (. = build context)
docker images                         # verify
docker run -d -p 8080:3000 --name web myapp:1.0
docker logs web
```

Useful build flags: `-t` (name:tag), `-f` (custom Dockerfile path), `--no-cache` (ignore cache), `--build-arg` (pass build variables).

## Image Optimization Basics

**1. Order instructions for layer caching.** Docker reuses unchanged layers. Put rarely-changing steps first (dependencies) and frequently-changing steps last (source code). That's why `package.json` is copied before `COPY . .` above.

**2. Use small base images.** `alpine` or `-slim` variants cut size dramatically.

| Image | Approx. size |
|---|---|
| node:20 | ~1 GB |
| node:20-slim | ~230 MB |
| node:20-alpine | ~140 MB |

**3. Use a `.dockerignore` file.** Keeps junk out of the build context:
```
node_modules
.git
*.log
.env
Dockerfile
```

**4. Combine RUN commands and clean up in the same layer.** Deleting files in a later layer doesn't shrink the image.

**5. Multi-stage builds.** Build in one stage, copy only the output to a lean final image:
```dockerfile
FROM node:20 AS build
WORKDIR /app
COPY . .
RUN npm ci && npm run build

FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 80
```

**6. Don't run as root.** Add `USER node` (or create a user) before `CMD`.

**7. Don't bake in secrets.** Never `COPY` `.env` files or put passwords in `ENV`/`ARG`; pass them at runtime.

## Quick Summary

| Instruction | When | Purpose |
|---|---|---|
| FROM | Build | Base image |
| WORKDIR | Build | Set working directory |
| COPY | Build | Copy files into image |
| RUN | Build | Execute commands, create layers |
| EXPOSE | Metadata | Document the port |
| CMD | Runtime | Default command (overridable) |
| ENTRYPOINT | Runtime | Fixed executable |
