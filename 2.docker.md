# Stage 2: Docker Commands

Each command is shown with its purpose and a practical example, using `nginx` as the demo image.

## 1. `docker pull`
Downloads an image from a registry (Docker Hub by default).
```bash
docker pull nginx            # latest tag
docker pull nginx:1.27       # specific version
```

## 2. `docker images`
Lists images stored locally.
```bash
docker images
docker image ls              # same thing, newer syntax
docker rmi nginx             # remove an image
```

## 3. `docker run`
Creates and starts a container from an image.
```bash
docker run nginx                          # foreground, blocks the terminal
docker run -d nginx                       # detached (background)
docker run -d --name web nginx            # give it a name
docker run -it ubuntu bash                # interactive terminal
docker run --rm alpine echo "hello"       # auto-remove after exit
```
| Flag | Meaning |
|---|---|
| `-d` | Run in background |
| `--name` | Custom container name |
| `-it` | Interactive + terminal |
| `-p` | Port mapping |
| `--rm` | Delete container on exit |
| `-e` | Set an environment variable |

## 4. `docker ps`
Lists containers.
```bash
docker ps          # running only
docker ps -a       # all, including stopped
docker ps -q       # only container IDs
```

## 5. `docker stop`
Gracefully stops a running container (SIGTERM, then SIGKILL after 10s).
```bash
docker stop web
docker stop $(docker ps -q)    # stop all running containers
```

## 6. `docker start`
Restarts a stopped container. Data and config are preserved, and no new container is created.
```bash
docker start web
docker restart web
```

## 7. `docker rm`
Deletes a stopped container.
```bash
docker rm web
docker rm -f web                  # force remove a running one
docker rm $(docker ps -aq)        # remove all containers
```

## 8. `docker logs`
Shows a container's output (stdout/stderr).
```bash
docker logs web
docker logs -f web          # follow live
docker logs --tail 20 web   # last 20 lines
```

## 9. `docker exec`
Runs a command inside a running container.
```bash
docker exec web ls /usr/share/nginx/html
docker exec -it web bash          # open a shell inside
```
Note the difference: `run` creates a new container, while `exec` works in an existing one.

## 10. Port mapping
Containers are isolated, so a port must be published to reach it from the host.
```bash
docker run -d -p 8080:80 --name web nginx
```
Format: `-p HOST_PORT:CONTAINER_PORT`. Open `http://localhost:8080` and you'll see the nginx welcome page.
```bash
docker run -d -p 8081:80 nginx    # second container, different host port
docker port web                   # show mappings
```
Two containers can't share the same host port, but they can both use port 80 internally.

## Suggested live demo flow
```bash
docker pull nginx
docker images
docker run -d -p 8080:80 --name web nginx
docker ps
docker logs web
docker exec -it web bash        # then: echo "Hello DevOps" > /usr/share/nginx/html/index.html
docker stop web
docker ps -a
docker start web
docker stop web && docker rm web
```

## Common student mistakes
- Forgetting `-d`, so the terminal appears "stuck".
- Trying to `rm` a running container (needs `stop` first, or `-f`).
- Reusing a `--name` that already exists, which errors until the old container is removed.
- Mixing up the port order (it's host:container, not the reverse).
